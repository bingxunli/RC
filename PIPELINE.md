# Pipeline — every command, end to end

This is the operational record of the analysis. Commands are given in the order
they were run. Paths are relative to the repository root unless absolute.

Conventions used below:

| Shell | Meaning |
|---|---|
| `bash` | Linux / WSL2 / Git Bash |
| `Rscript` | R 4.4.0 |
| `python` | the venv from `env/setup_wsl.sh` |

Outputs are written next to the inputs under `work/` in the original project;
here they are shown as `magma/`, `pops/`, `flames/`, `smr/` for brevity.

## 5. MAGMA (three steps)

The gene-level statistics consumed by PoPS and FLAMES are FUMA's. To reproduce
them from scratch (needs the MAGMA binary, which the original workstation could
not download — `cncr.nl` and `vu.data.surafsara.nl` were both unreachable):

```bash
# 5a. build the SNP/P/N input  (11,071,938 rows)
bash code/04_magma/make_sumstats.sh "data source/RC.txt" magma/RC_magma.sumstats

# 5b. annotate -> gene analysis -> gene-property
MAGMA=./magma \
BFILE=g1000/g1000_eur \
GENE_LOC=NCBI37.3.gene.loc \
SUMSTATS=magma/RC_magma.sumstats \
OUT=magma/RC \
THREADS=8 \
bash code/04_magma/run_magma.sh
```

`--gene-model snp-wise=mean` is deliberate: it is the model PoPS and FLAMES
expect, and it is what FUMA used.

Sanity checks that the run is comparable to FUMA's:

```bash
# N must span 570,662 / 434,646 / 136,016 and nothing else
awk 'NR>1{print $7}' magma/RC.genes.out | sort -u | tail

# NSNPS is the reference-panel x GWAS intersection, not the bim window size:
#   PCSK9 141/240, CETP 130/260, ALDH1A2 2614/5507, SORT1 185/533, HMGCR 61/147
# ratio 0.35-0.59, matching 11.07M / 22.67M = 0.49
```

## 6. PoPS

### 6.1 The gene-universe constraint

`pops.py` builds its error covariance from `gene_annot_df.loc[Y_ids].CHR`, i.e. it
requires the annotation to cover **every** gene in the MAGMA output. The PoPS
feature matrices cover 18,383 genes; MAGMA reports 18,952. Running directly fails:

```
KeyError: "['ENSG00000269831', ...] not in index"
```

Fix: restrict MAGMA to the feature genes first, **including the trailing LD
correlation block of `.genes.raw`** — otherwise PoPS's error covariance is
mis-aligned and the run silently produces wrong standard errors.

```bash
python code/04_magma/subset_magma_genes.py \
    magma/magma.genes.out \
    magma/magma.genes.raw \
    pops/features/gene_annot.txt \
    pops/run_full/magma_pops18383
# -> 18,952 -> 17,999 genes; 384 feature genes absent from MAGMA
```

### 6.2 Run

```bash
POPS_PY=$HOME/pops/pops-src/pops.py \
FEAT_DIR=$HOME/pops/features/pops_features_full \
MAGMA_PREFIX=pops/run_full/magma_pops18383 \
OUT=pops/run_full/RC_pops_full \
NCHUNKS=116 \
PYTHON=python \
bash code/05_pops/run_pops.sh
```

### 6.3 Sensitivity analysis

```bash
# 99 chunks instead of 116 -- the "pathway-naive" feature set
NCHUNKS=99 \
FEAT_DIR=$HOME/pops/features/pops_features_pathway_naive \
OUT=pops/run_pathway/RC_pops_pathway_naive \
bash code/05_pops/run_pops.sh
```

Result: this feature set pushes `UBC` (housekeeping artefact) to rank 1 and drops
`CETP` to 673, `HMGCR` to 3,435. It is the argument for using the full set.

## 8. FLAMES

### 8.1 Annotation (110 loci)

`annotate.py` compiles variant→gene evidence per locus: CADD, eQTL (CLPP), Hi-C,
VEP consequences, promoter capture. It needs one `cred1` credible-set file per
locus and an `indexfile` mapping locus → file.

```bash
python code/06_flames/flames_patched/annotate.py \
    --index_file  indexfile.txt \
    --Annotation_dir  annotation_data \
    --build GRCh37 \
    --pops_out   pops/my_trait.preds \
    --magma_z    magma/magma.genes.out \
    --magma_tissue magma/magma_exp_gtex_v8_ts_avg_log2TPM.gsa.out \
    --outdir annots \
    --SNP_col cred1 --prob_col prob1 \
    --loci FUMA_job714838/GenomicRiskLoci.txt \
    --genes FUMA_job714838/genes.txt \
    --filter 750000
```

### 8.2 Scoring

```bash
python code/06_flames/flames_patched/optimize_FLAMES.py \
    --model_dir flames_model \
    --input annots/annotated_locus_*.txt \
    --pops_combi 0.725 \
    --filt 750000 \
    --outdir flames \
    --name FLAMES_scores
```

The scoring chain (port of `optimize_FLAMES.py::Flames_scoring`):

```
rel_XGB    = XGB / max(XGB)                                    # within locus
rel_PoPS   = MinMaxScaler(0.292, 1).fit_transform(PoPS)        # within locus
             / max(...)
FLAMES_raw = XGB*rel_PoPS + 0.583*XGB*rel_PoPS.astype(int)      # +58.3 % if PoPS is #1
FLAMES_scaled = FLAMES_raw / sum(FLAMES_raw)
FLAMES_causal = (raw > 0.134) & (scaled > 0.248) & is_highest
ECP        = 1.5776s^3 - 2.7616s^2 + 1.8136s + 0.4460          # capped at 1
```

### 8.3 Rebuilding the 21 missing credible sets

21 loci had no credible set in the delivered fine-mapping output. Rebuilt with
`code/06_flames/rebuild_21_loci/`:

```bash
python code/06_flames/rebuild_21_loci/gen_cred1.py       # -> cred1_rebuilt/
python code/06_flames/rebuild_21_loci/run_annotate_rebuilt.py
python code/06_flames/rebuild_21_loci/run_scoring_rebuilt.py
```

The scripts are idempotent per locus and retry 3x on network failure (the CADD
lookups are remote).

### 8.4 Re-scoring with a refreshed PoPS run

Because `select_features` in `FLAMES_scoring.py` drops any feature containing
`"rel"`, `"PoPS"`, `"MAGMA"` or `"dist"`, `XGB_score` is **independent of PoPS**.
PoPS enters only through the `PoPS_Score` column. The whole score chain can
therefore be recomputed from an existing `.raw` file without re-annotating
(~1.5 h for 110 loci at ~50 s each).

```bash
python code/06_flames/rescore_flames_pops.py \
    pops/run_full/RC_pops_full.preds \
    flames/rerun/FLAMES_scores_newpops \
    flames/FLAMES_scores.raw \
    flames_rebuilt_scores/FLAMES_scores_rebuilt.raw
```

Two traps this script handles:

1. The `locus` column of a `.raw` file is `pd.factorize(filename)[0]`, so two
   runs collide. The real FUMA locus id is re-extracted from the filename
   (`annotated_locus_(\d+)`).
2. `rel_PoPS_Score` must be recomputed with `MinMaxScaler(feature_range=(0.292,1))`
   fitted **per locus**, not carried over.

If the annotation step ever has to be re-run instead, use
`code/06_flames/refresh_flames_pops.py`, which rewrites `PoPS_Score` in place in
the `annotated_locus_*.txt` files and deletes the derived `rel_PoPS*` columns.

## 9. SMR and colocalization

### 9.1 Rebuild the GWAS input with the corrected SE

`RC.txt` was produced with `se = 1/sqrt(2f(1-f)·f·(N+Z²))` — one extra `f`. The
correct form (Zhu et al., PMID 27019110) is `se = 1/sqrt(2f(1-f)(N+Z²))`, so

```
se_ok = se_bug * sqrt(f)      beta_ok = beta_bug * sqrt(f)      z, p unchanged
```

MAGMA, PoPS and FLAMES never read β/SE, which is why none of them moved. SMR
does, so its input has to be rebuilt.

```bash
python code/07_smr_coloc/build_smr_input_fixed.py      # -> smr/RC_smr_fixed.txt
python code/07_smr_coloc/subset_smr_gwas.py            # -> smr/RC_smr_fixed_besd.txt
```

The subset keeps only SNPs present in the union of the 49 GTEx v8 besd files
(3,313,991 of 11,071,938). Results are identical to the full-file run — checked
by `code/07_smr_coloc/ab_check_smr.py` — and the run is ~7x faster.

### 9.2 Run

```bash
# subset the LD reference to the same SNP list first
plink --bfile g1000/g1000_eur --extract <snp_list> --make-bed --out g1000/gtex8

SMR_BIN=./smr \
GWAS=smr/RC_smr_fixed_besd.txt \
BEQTL_DIR=eqtl/GTEx8 \
BFILE=g1000/gtex8 \
OUTDIR=smr/gtex8_out \
PARALLEL=12 \
bash code/07_smr_coloc/run_smr_gtex8.sh
```

`--thread-num` buys almost nothing here (each `smr` process sat at ~1 core);
throughput comes from `PARALLEL`. Budget ~1.2–1.6 GB resident per tissue.

### 9.3 Summarise

```bash
python code/07_smr_coloc/summarize_smr_gtex8.py smr/gtex8_out
python code/07_smr_coloc/summarize_decode_smr.py        # plasma pQTL
```
